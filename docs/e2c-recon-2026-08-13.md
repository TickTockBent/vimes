# E2-c recon — git touchpoint map (agent report, 2026-08-13, verified excerpts)

*(Read-only recon for the E2-c frame; full verdict table at bottom. The
orchestrator spot-verifies load-bearing rows before building on them.)*

**Headline:** `packages/daemon/src/gitAdapter.ts` ALREADY IS the single
injection-guarded git seam — the only `execFile('git', …)` in the repo
(`defaultGitRunner`, :42-62), with read verbs (repoRootFor/status/diff/
branches/worktrees) and write verbs (stage/unstage/commit), a cached
`git --version` preflight, and `GitOpError = 'git-unavailable' |
'not-a-repo' | 'git-failed'` + discriminated `GitOpResult<T>`. E2-c is
"add create/open/remove to the existing adapter, absorb worktreeManager,
add the two pinned gates" — not "build an adapter."

**The write half to absorb:** `worktreeManager.ts` (335 ln) — `ensureWorktree`
(`git worktree add -b <branch> -- <path>`), `removeWorktree`
(`git worktree remove -- <path>`, deliberately does NOT delete the branch),
`findExistingWorktree` (worktree list --porcelain), plus a private `runGit`
duplicating `GitAdapter.run`.

**Pin 1 lands at `worktreeManager.ts:296-301`:** `findExistingWorktree`
matches path OR BRANCH and returns `reused: true` — i.e. today `create`
silently performs `open`. The split: `create` gains a new `GitOpError`
member (candidate `'branch-already-checked-out'`) naming the existing path;
`open` is the verb that consumes it. Provenance schema already exists:
`nodeProvenanceSchema` (`events.ts:1150-1155`) carries
`{branch, baseRef, resolvedCommit, path}` — `resolvedCommit` differing
between create and open is exactly why merging the verbs lies.

**Pin 2 (remove gate):** entirely missing today — `removeWorktree` has ZERO
production callers (nothing cleans up; deliberate, "a decision record, not
a patch"). The gate's query: sessions projection where
`session.cwd === <checkout path>` AND non-empty `claudeSessionIds`.
⚠ Read the SESSIONS PROJECTION, not discovery (`discovery.ts:16-20` only
sees project-root cwds) and NEVER compute transcript paths (D45: discovered,
never computed).

**Provenance seal opens in this slice:** `nodeWriter.ts:44-49,:293` stamps
`provenance: null` unconditionally and `nodeApi.ts:91-96` strips smuggled
provenance — recorded in slice-14 as "provenance arrives with the E2-c
unit." The fold's write-once enforcement (`nodes.ts:105-108,146`) must NOT
be relaxed. `node_created` already models worktree nodes; only an emitter
is missing.

**Branch naming to rewrite:** `core/tasks/worktreePaths.ts` —
`TASK_WORKTREE_BRANCH_PREFIX = 'vimes/task-'` (tenant word; migration-map
:102 says engine-derived rewrite). ⚠ The injective `escapeToSafeCharset`
+ FNV-1a fingerprint SURVIVE VERBATIM — they are why hostile ids can't
traverse or collide.

**Guarding precedent (copy verbatim):** execFile + array args (never shell
strings); `--` before every request-derived operand; `resolveWithinRoots`
triple-check (`gitApi.ts:140,151,183` — requested root, discovered
toplevel, request paths); injective escaping at name-derivation.

**Free foothold:** `GET /api/git/worktrees` (gitApi.ts:381-396) is built,
shipped, and UNCONSUMED by any UI — the natural read half of the surface.

**Hazards recorded:**
- **Allowlist liveness:** a worktree cwd is in the git-API allowlist only
  while its session is live (`app.ts` union with `liveSessionCwds()`), so
  "inspect this checkout" 403s the moment the worker dies. Any human-facing
  open/inspect verb must reckon with it.
- **Attribution gap (known, decisions ~1347):** worktreeRoot is
  deliberately outside every project root, so prefix attribution dumps
  worktree sessions to no-project — under slice 15's tree, worktree
  sessions land in `unfiled`. Correct attribution needs the
  taskRef→projectRoot join; cost rows carry no taskRef. Bites when
  `VIMES_WORKTREE_ISOLATION` flips on (default off; NO production worktree
  has ever been created).
- **No-fallback invariant must hold:** `worktree-failed` → nothing spawns
  (`taskDispatcher.ts:84-88,313,542-562`); dispatcher becomes a CALLER of
  the new verbs.

**Verdict table:** gitAdapter runner/parsers CONSUME (extend in place) ·

CONSUME (off-by-default is the safety property) · cwd-resume chain
